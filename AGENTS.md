# Mira project guidance

- Demo direction: we do not want to hold back on technology or capabilities. Build compelling, visually rich, working experiences that show what Mira can do. Do not use production readiness, generic privacy/guideline concerns, or the word "demo" to default to static worksheets or remove useful capabilities. Address concrete implementation issues directly and track later hardening separately. See `PRD/mira_activity_upgrade_plan.md` for the separate upgrade proposal and implementation sequence.
- `PRD/mira_prd.md` defines approved V0 behavior and product scope. Skills may guide implementation of that scope; they do not authorize new screens, flows, data retention, integrations, actions, or clinical behavior.
- Use Expo's official docs and Codex plugin for Expo SDK, Expo Go, development builds, and `expo-audio` behavior.
- Use Software Mansion's React Native skills and official docs for React Native/New Architecture, Gesture Handler, Reanimated, and its audio APIs if one is selected. Check the installed package versions before relying on version-specific APIs.
- Check the installed Gesture Handler major before choosing its v2 or v3 API. If Reanimated 4 worklets call back to the React Native thread, use `scheduleOnRN`; do not use deprecated `runOnJS`. Do not add gesture or animation libraries solely for polish.
- Use OpenAI's official docs for Realtime session and event behavior, and the selected React Native WebRTC library's docs for its native integration. Expo audio capture does not replace the approved WebRTC voice path.
- Use UI/UX Pro Max only for visual/design judgment: color, typography, spacing, hierarchy, and accessibility presentation. It cannot expand product requirements or justify unrelated dependencies.
- Preserve the approved explicit push-to-talk behavior: mic off by default, hold to speak, release to end the turn, no automatic VAD. Use a press/gesture API that matches installed versions; do not add unrelated gestures.
- Mira V0 targets modern Android devices with a normal React Native/Expo app; the OnePlus is the primary physical QA/demo phone. Record Android version for the voice gate; check exact model only if a compatibility issue appears.
- Keep OpenAI Realtime selected for V0. If realtime voice disconnects, preserve current conversation/context and offer Retry voice or Continue with text through the existing OpenAI/FastAPI integration. If provider/server is unavailable, label Mira temporarily offline while Journal drafts and previously loaded Actions remain usable.
- `task_reset_60s` and `pause_60s` are neutral, non-clinical demo placeholders, not treatment; Mpower clinicians later decide suitability, wording, and when to offer interventions.
