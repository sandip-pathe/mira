Date: 2026-10-13. Reviews: plan-ceo-review, plan-eng-review. Status: implemented; physical provider/device acceptance remains.

## Goal and boundaries

“I'm burned out and can't focus” → understand the immediate need → listen or clarify → offer a small action with permission → guide it → ask whether it helped → remember a useful outcome only with explicit consent.

The user's v0.02 request replaces transcript-first Talk with a state-led moment and removes the separate Actions destination. Actions happen in Talk; Journal remains separately reachable. Update `mira_prd.md` to make this the new V0 direction. Journal sharing, explicit push-to-talk, OpenAI Realtime, text recovery, persistent Help, and non-clinical boundaries carry forward.

No RAG, extra providers/models/actions, dashboards, mood tracking, community, booking, multi-agent support brain, or major visual redesign.

## Premise and reuse

The pain is being heard but still left to work out the next step. The proposed experience addresses it directly only if listening remains a valid result and the action changes in response to the user's input. A new screen alone will not prove the thesis.

Reuse `mobile/src/voice.ts` for voice/interruption/tool relay, `Mira.tsx` for moment state and navigation, `Actions.tsx` for the embedded activity, `server/app.py` for bounded tools and prompts, and `server/store.py` for consented context. Do not add a support-state file/service or rebuild working voice. No Git repository is present at this project root; branch/history/PR evidence is unavailable.

## Experience skeleton

```text
What is going on? → listen / clarify
                         |
                  permission to try?
                 no /           \ yes
        continue listening       two choices / not now
                                     |
                              guided action
                                     |
                         outcome → optional memory consent
```

Current state fields: `what_happened`, `current_need`, `what_is_unclear`, `support_mode`, `suggested_action`, `previously_helpful`. These describe a tentative understanding, not a diagnosis. Approved modes: listen more, clarify, offer action, continue action, check outcome, suggest human support. The five-minute focus attempt is optional and user-controlled; never auto-start it.

Visible UI state must come from actual connection/action state; model prose cannot claim an action started, completed, or a memory saved. Keep captions accessible without making transcript cards the default. Typing remains available. “Not now”, stop, pause, skip, and Help remain reachable.

## Review findings

- **Scope:** Two destinations remain: Talk (the complete moment experience) and Journal. Remove Actions from bottom navigation; open the action flow inline in Talk. This is directly requested by “Kill the mental model that users ‘go to the Actions tab.’” No new service or model.
- **Action fidelity:** Existing catalog behavior in `server/app.py` is fixed and its task reset is not a dump-and-sort activity. Interactive sorting must use user-visible, editable suggestions and a selected task; do not claim the model-organized list is objective or persist the dump. Preserve the approved fixed action IDs and neutral placeholder content; if the current catalog cannot support the described guided flow, surface that gap rather than silently inventing intervention steps.
- **State and errors:** A tentative support state must survive voice reconnect/text fallback during the active session, and reset at the intended session boundary. Failed/empty model response leaves the person able to continue listening or type. Disconnected voice offers retry/text and preserves context; offline mode does not claim feedback or memory saved. Action decline/stop returns to listening without pressure.
- **Consent:** Pre/post stuck check is optional and neutral. Store the specific useful lesson only after a distinct, explicit future-use choice; rating alone is not consent. Keep it separate from Journal approval, identify source on later use, support revocation/deletion through existing controls, and do not persist raw dump or Talk transcript.
- **Verification:** Focused regression checks for support-mode transitions/decline, action sorting correction and tiny-task selection, interrupted 5-minute timer, outcome consent denied/granted/revoked, and voice-to-text recovery. Use the existing contract tests and one device walkthrough; avoid broad test infrastructure.
- **UI:** Put “What’s going on?” and hold-to-talk first, then a compact state label and current next step. Transcript is secondary and available; show connection/errors, timer controls and next actions accessibly, with navigation and Help reachable. No redesign dependency.

### User-visible result

The app opens in **Talk**. The bottom navigation has **Talk** and **Journal**; there is no Actions destination. Talk opens with “What’s going on?”, the existing hold-to-talk control, and a compact state such as Listening, Thinking, or Trying one small step. Transcript/captions remain available lower in the view. Help and text continuation remain reachable.

When the conversation suggests overwhelm or focus difficulty, Mira reflects the tentative understanding and asks whether the person wants one small step. “Not now” returns to listening. With permission, Mira offers only the existing Task reset and 60-second pause. The task reset accepts a typed or dictated brain dump, proposes editable **Now / Later / Ignore** buckets, lets the user correct them and choose exactly one small task, then offers an optional 5-minute attempt. The task reset’s sort step does not run a timer; the focus attempt is its optional five-minute substep. Pause remains 60 seconds. Stop stays available; backgrounding pauses either timer. Afterward Mira asks “Any better?” and what helped. Declining memory consent discards the proposed lesson. With consent, show the exact short lesson before saving it for future use.

### Implementation shape

No separate support-brain agent or service. Keep the tentative fields (`what_happened`, `current_need`, `what_is_unclear`, `support_mode`, `suggested_action`, `previously_helpful`) in active Talk state in `Mira.tsx`; clear them at the session/reset boundary and preserve them across voice retry/text continuation. Add one bounded `update_moment_state` function tool using enumerated support modes and capped text fields; its validated result updates the Talk state label. The model may propose a state and next step; the UI advances only on explicit user action or a confirmed tool result. “Suggest human support” points only to the existing Help placeholder.

For categorization, let the user enter the dump as editable lines in the task-reset activity, then call `POST /sessions/{id}/task-reset/organize` with those lines. Responses structured output returns only `Now / Later / Ignore` arrays of input indices. FastAPI checks that every index appears exactly once, then maps the indices back to the original strings; the provider cannot invent, rewrite, omit or duplicate task text in the displayed result. The endpoint stores no dump. If sorting fails, show the original lines and allow manual category placement or direct task selection. Existing `select_actions` remains the only action-offer tool and returns only the two catalog entries after permission. For moment status, Realtime uses one bounded `update_moment_state` function tool and text fallback returns the same schema with Responses `text.format` JSON Schema. Both are validated before changing UI. This avoids a new service or multi-call text tool loop. Official OpenAI docs distinguish function calling for app-executed tools from structured output for shaping an answer; they confirm function results travel as `function_call_output` over the Realtime event surface and JSON Schema is supported by Responses. ([Realtime tools](https://developers.openai.com/api/docs/guides/realtime-mcp), [structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)).

Run the guided flow inside the current `Actions.tsx` component rendered from Talk, not as a tab. Keep the 60-second pause unchanged; make task reset interactive. Keep action run writes and the existing neutral rating. Extend the consented feedback record with the exact user-approved helpful lesson; default reuse remains off. Add a nullable SQLite field with an additive startup migration. Provide revocation/deletion through the existing feedback controls and identify the lesson source whenever it is reused. Do not store the dump or Talk transcript.
